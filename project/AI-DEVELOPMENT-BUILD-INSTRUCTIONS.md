## 1. SOURCE OF TRUTH

* Always start from the newest verified build.
* Never overwrite an existing build.
* Give each new build a unique filename/version number.
* Preserve previous builds for rollback.
* A build becomes the new source of truth only after verification.

## 2. CLEAN PRODUCTION CODE

* Implement changes directly in the proper production code.
* Avoid patch-on-patch fixes and duplicate implementations.
* Maintain one authoritative implementation per feature.
* Remove obsolete code when replacing functionality.
* Remove dead code, duplicate CSS/JS, conflicting rules, unused assets, unnecessary dependencies, broken references, debug code, experiments, and temporary workarounds.
* Leave every completed build clean and maintainable.

## 3. PRESERVE APPROVED WORK

* Do not redesign approved work unless specifically requested.
* Preserve approved layouts, fonts, colors, spacing, sizing, and component styles.
* Preserve existing functionality, navigation, business rules, permissions, and behavior.
* Change only what is necessary.

## 4. WORK INDEPENDENTLY

* When given an idea, determine the best professional technical implementation.
* Make reasonable engineering decisions without requiring every technical detail from me.
* Do not repeatedly stop for approval.
* Ask only when there is a genuine blocker or important decision that cannot safely be determined.

## 5. DEVELOPMENT PHASES

* Break large work into logical phases.
* Complete each phase before moving forward.
* Keep phases isolated enough to troubleshoot independently.
* After each phase: **build → audit → test → fix → verify**.
* Continue automatically unless I tell you to stop.

## 6. FULL QUALITY AUDIT

After every edit, review the entire affected build, not only changed lines.

Check for:

* Syntax, structural, and runtime errors.
* Duplicate/conflicting CSS, JS, functions, IDs, or event handlers.
* Broken imports, references, assets, navigation, and dependencies.
* State, async, permission, and regression issues.
* Broken buttons, menus, forms, modals, and important workflows.
* Stale or unused code.

## 7. VERIFY BUILDS — CRITICAL

* Never assume code works because it looks correct.
* Actually verify whenever technically possible.
* Confirm the app launches and important workflows function.
* Test buttons, navigation, forms, integrations, exports, installers, and connections when applicable.
* Check runtime and console errors.
* Never claim something is working, connected, synchronized, saved, uploaded, tested, or production-ready unless verified.
* If credentials, APIs, hardware, certificates, servers, or external dependencies prevent verification, briefly state what remains unverified.

## 8. 1 CLEAN PASSES

* Every final build must pass **ONE clean audit/test passes**.
* must test the exact same final build.
* If anything is fixed, restart the one-pass verification.

## 9. DESIGN — PREMIUM, CLEAN, UNCLUTTERED

* Prioritize clarity, breathing room, spacing, and visual hierarchy.
* Clearly separate sections.
* Use screen space efficiently without crowding.
* Avoid unnecessary buttons, duplicate actions, excessive information, and filling empty space just because it exists.
* Keep everyday functions easy to access.
* Maintain balanced spacing between controls, text, panels, and content.

## 10. NO FAKE FUNCTIONALITY

* Never fabricate functionality, results, integrations, data, or successful tests.
* Do not make unfinished features appear functional.
* Implement and verify everything technically possible.
* Clearly identify external blockers instead of pretending work is complete.

## 11. COMMUNICATION

* Keep responses extremely brief, usually **1–3 short sentences**.
* Do not narrate routine development work.
* Avoid long technical reports and repeated summaries.
* Focus on execution.
* When successful, briefly state what was completed and whether verification passed.
* When blocked, briefly state the issue and what is needed.
* I will ask if I want more detail.

## 12. FINAL STANDARD

Every iteration must leave the project:

* Cleaner.
* Stronger.
* Verified.
* Easier to maintain.
* Free of unnecessary remnants.
* Protective of approved work.

Never sacrifice project quality just to finish faster.
